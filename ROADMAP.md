# ViridisOS public roadmap

## Release foundation

- Seal the open-source payload and exclusion manifest.
- Pass core, integration, packaging, adapter, and clean-install tests.
- Publish a standalone repository only after exact release authorization.
- Label all development certificates as self-rooted and preview-only.

## Builder path

- Ship one minimal module template and a sub-ten-minute reproduction.
- Add structured module, reproduction, and field-validation issues.
- Accept the first outside reproduction before claiming builder engagement.
- Record named independent evidence in `NETWORK_EFFECT_EVIDENCE.json`.

## Research-to-product path

- Keep the seven 2026-08-15 results in `BACKLOG_NO_WRAPPER` until each adapter
  separately declares inputs, units, uncertainty, refusal behavior, and tests.
- Prioritize the Seed-Source Bottleneck Certificate for a restoration
  decision-support prototype when rights-cleared field inventory exists.
- Never promote Working Corpus research to the Canon spine or production by
  module-count or publication alone.

This roadmap is directional. It does not authorize publication, repository
visibility, production signing, mark use, settlement, or deployment.
